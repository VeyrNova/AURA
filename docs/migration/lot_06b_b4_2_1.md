# LOT 6B-B4.2.1 — real Calendar write validation

Technical preparation is complete; real validation is intentionally manual.
`tests/native/_evidence/lot6b_b421_calendar_write_real.py` validates only the
Calendar create/readback/update/readback/delete/readback sequence. Every
mutation requires `--confirm-real-write`. The test title is
`TEST AURA — À SUPPRIMER`, and the state file stores only event id, title,
times and phase. Duplicate creation is blocked until the active event is
deleted.

Tasks writes and B4.2.2/B4.3 are out of scope. No real operation is launched
automatically by tests. PreparedAction E2E and cancel remain separate manual
checks before declaring the lot fully PASS.

Delete readback treats HTTP 404/410 and a returned event with
`status="cancelled"` as deleted. Read-only `--status` repairs an existing
state file to `phase=deleted` without issuing another delete.

The final E2E harness is `tests/native/_evidence/lot6b_b421_calendar_e2e_real.py`.
It uses GoogleAuthProvider, GoogleCalendarProvider, PreparedActionRepository,
CalendarService, PendingActionOrchestrator and LocalBus. Confirm and cleanup
mutations require `--confirm-real-write`; prepare and cancel are non-mutating.
The state directory is UTF-8 JSON and stores only identifiers, title and
phases. Tasks and B4.2.2 remain out of scope.
